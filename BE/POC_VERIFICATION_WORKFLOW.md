# PoC Verification Workflow

## 📋 Overview

PoC (Proof of Concept) verification workflow integrates LLM Module, Backend, and Sandbox Module to automatically verify vulnerability exploits.

---

## 🔄 Complete Flow

```
LLM Module → Generate PoC → BE Storage → User Verify → Sandbox Execute → Classify → Update Status
```

---

## 📍 Step-by-Step Process

### 1. **LLM Module Generates PoC**
- **Input**: Vulnerability information from SAST scan
- **Process**: LLM analyzes vulnerability and generates exploit code
- **Output**: PoC file saved to `/tmp/{project_name}/TP/PoC/{filename}`
- **BE Action**: Create PoC record in database with `is_verified=False`

```python
# LLM Module will save PoC file here (before verification)
/tmp/{project_name}/TP/PoC/{poc_filename}
```

### 2. **User Triggers Verification**
- **Frontend**: User clicks "Verify PoC" button in True Positive Report page
- **API Call**: `POST /api/pocs/{poc_id}/verify`
- **Backend**: Receives request and locates PoC file

### 3. **Backend Sends to Sandbox**
```python
# Backend code
from app.services.sandbox import verify_poc

sandbox_result = verify_poc(
    poc_file_path="/tmp/project/TP/PoC/exploit.py",
    vulnerability_info={
        "type": "SQL Injection",
        "severity": "HIGH",
        "target": "http://target-app.com"
    }
)
```

### 4. **Sandbox Executes PoC**
- **Environment**: Isolated sandbox environment
- **Process**: 
  - Execute PoC code
  - Monitor execution
  - Capture results
  - Determine if exploit succeeded

### 5. **Sandbox Returns Result**
```json
{
    "success": true,
    "exploitable": true,
    "execution_log": "PoC executed successfully. Gained unauthorized access.",
    "classification": "real_poc",
    "execution_time": 2.3,
    "sandbox_id": "sandbox-12345"
}
```

### 6. **Backend Classifies and Moves File**

#### If Exploit Successful (Real PoC):
```python
# Move to Real_PoC folder
/tmp/{project_name}/TP/PoC/Real_PoC/{poc_filename}

# Update database
poc.poc_type = "real_poc"
poc.is_verified = True
poc.is_downloadable = True
poc.actual_result = "Exploit successful"
```

#### If Exploit Failed (Poor PoC):
```python
# Move to Poor_PoC folder
/tmp/{project_name}/TP/PoC/Poor_PoC/{poc_filename}

# Update database
poc.poc_type = "poor_poc"
poc.is_verified = True
poc.is_downloadable = True
poc.actual_result = "Exploit failed - properly mitigated"
```

### 7. **Return Result to User**
```json
{
    "id": 1,
    "vulnerability_id": 123,
    "poc_type": "real_poc",
    "poc_name": "sql_injection_exploit.py",
    "is_verified": true,
    "is_downloadable": true,
    "actual_result": "Exploit successful",
    "created_at": "2026-02-08T13:00:00"
}
```

## 🔌 API Endpoints

### Verify PoC
```http
POST /api/pocs/{poc_id}/verify
Authorization: Bearer {token}
```

**Response:**
```json
{
    "id": 1,
    "vulnerability_id": 123,
    "poc_type": "real_poc",
    "poc_name": "exploit.py",
    "description": "SQL Injection exploit",
    "is_verified": true,
    "is_downloadable": true,
    "created_at": "2026-02-08T13:00:00"
}
```

### Download Verified PoC
```http
GET /api/pocs/{poc_id}/download
Authorization: Bearer {token}
```

### Preview PoC Content
```http
GET /api/pocs/{poc_id}/preview
Authorization: Bearer {token}
```

**Response:**
```json
{
    "id": 1,
    "poc_type": "real_poc",
    "file_path": "/tmp/Project/TP/PoC/Real_PoC/exploit.py",
    "has_file": true,
    "file_content": "#!/usr/bin/env python3\n..."
}
```

## 📊 Database Schema Updates

### PoC Table Fields:
- `poc_type`: `"real_poc"` or `"poor_poc"`
- `is_verified`: `boolean` - Whether sandbox has verified
- `is_downloadable`: `boolean` - Whether user can download
- `actual_result`: `text` - Sandbox execution result
- `poc_path`: `string` - Full path to PoC file

## 🎯 Frontend Integration

### True Positive Report Page

```javascript
// When user clicks "Verify PoC"
async function verifyPoC(pocId) {
    const response = await fetch(`/api/pocs/${pocId}/verify`, {
        method: 'POST',
        headers: {
            'Authorization': `Bearer ${token}`
        }
    });
    
    const result = await response.json();
    
    if (result.poc_type === 'real_poc') {
        showSuccess('✅ Real PoC - Exploit successful!');
        enableDownloadButton(pocId);
    } else {
        showWarning('⚠️ Poor PoC - Exploit failed');
    }
}

// Download verified PoC
async function downloadPoC(pocId) {
    window.location.href = `/api/pocs/${pocId}/download`;
}
```

## 🔐 Security Considerations

1. **Sandbox Isolation**: PoCs must execute in completely isolated environment
2. **File Validation**: Validate PoC files before sending to sandbox
3. **Rate Limiting**: Limit verification requests to prevent abuse
4. **Access Control**: Only TP vulnerabilities can have PoCs
5. **Audit Logging**: Log all PoC verifications and executions
